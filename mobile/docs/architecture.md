# kamci mobile: Architecture Overview

_Purpose: get oriented quickly without scanning the whole repo. Read together with
`README.md` (commands, setup) and `docs/api-contracts.md` (backend contract)._

## Layers
Feature-first with `data` / `domain` / `presentation`. Each feature has
`data/{datasources,models,repositories}`, `domain/{entities,repositories,usecases}` and
`presentation/{screens,widgets,providers}`.
Most features skip the `usecases` layer and call the repository directly from the provider
(auth has `RegisterUsecase` / `LoginUsecase`, but they are not used: the provider calls
the repository directly).

## Features and screens
| Feature | Screens | Main provider(s) |
|---|---|---|
| auth | splash, login, register, forgot-password, reset-password, change-password | `auth_provider.dart` (`authNotifierProvider`: login/register/logout/refresh state), `change_password_provider.dart` |
| debt | debt_list, debt_detail, debt_form | `debt_providers.dart` (grouped list, create/update/pay/skip/bulkPay/delete) |
| category | category_list, category_detail | `category_providers.dart` (CRUD + member management) |
| income | income (list + add) | `income_providers.dart` |
| subscription | premium_screen | `subscription_providers.dart` (status + IAP verify) |
| charts | charts_screen | `charts_providers.dart` → `DebtRemoteDatasource.getSummary` |
| settings | settings_screen | `app_settings_provider.dart` (core): language / theme |

Shared: `core/providers/current_user_provider.dart` (extracts userId/email from the JWT),
`shared/providers/` (bottom nav and other UI state).

## Routing (go_router, `core/router/app_router.dart` + `route_names.dart`)
`RouteNames` / `RoutePaths` constants: splash, login, register, forgot-password,
reset-password, debts (+new/detail/edit), categories (+detail), settings,
change-password, income, charts, premium. The redirect logic reads the auth state
(`authNotifierProvider`). **Router debug logging is guarded by `kDebugMode` and is off in
production; keep that guard.**

## Network layer
`core/network/dio_client.dart`: `dioClientProvider` (AuthInterceptor, plus
LoggingInterceptor in debug) and `refreshDioProvider` (no interceptors, used for
login/register/refresh/logout). `AuthInterceptor` handles 401/403 and the gateway
`TOKEN_EXPIRED` / `TOKEN_INVALID` / `AUTH_HEADER_*` codes with refresh-then-retry or a
forced logout.
`core/network/api_exception.dart` maps every error to a typed exception and
`core/l10n/exception_l10n.dart` turns those into locale-specific messages. When adding a
new backend error code, update **both**, add a key to `l10n/app_*.arb` and run
`flutter gen-l10n`.

## State and codegen notes
- Riverpod: `@riverpod` + `riverpod_generator`. After adding or changing a provider,
  run `dart run build_runner build --delete-conflicting-outputs`.
- Models: freezed + json_serializable, generated by the same command.
- i18n: `lib/l10n/app_tr.arb` (template) + `app_en.arb` → `flutter gen-l10n` →
  `lib/gen/l10n/` (never edited by hand).

## Keeping this up to date
After a significant architecture or contract change (new feature, provider structure
change, new route), update this file and `docs/api-contracts.md`. Keep both short.
